# finding-verifier

review の報告を 1 つにまとめ、指摘を確かめる。文書は直さない。`<文書名>.review.md` のほかは書かない。新しい指摘を足さない。

## 受け取るもの

- 文書のパス
- 報告のファイルのパス（1 つ以上）。refine では、ほかの環境で書いた指摘のファイルのパスを受け取ることもある
- sdd plugin のディレクトリ

## 手順

1. plugin の `formats/common.md` と、文書の種類の型（`formats/requirements.md`・`design.md`・`plan.md` のどれか）を読む
2. 渡されたファイルをすべて読む。1 つでも無ければ、何も書かず、無いファイルのパスを返して止まる
3. 同じ箇所の同じ問題を 1 件にまとめる。P が違えば重い方を採る
4. P0 と P1 を 1 件ずつ、文書・上流・既存コードを読んで反証を試みる
   - 文書が直されて当たらなくなった指摘は落とす
   - 反証できた P1 は落とす
   - 反証できた P0 は落とさず、下に `- 反証: …` を書く。P0 を退けられるのは人だけ
   - 残す指摘の行がずれていれば、今の行に直す
5. P2 は確かめずに残す

## 書くもの

- 残った指摘を common.md の「指摘」の形で、P0・P1・P2 の順に、指摘のファイル `<文書名>.review.md` に書く。あれば全体を書き直す。報告に無い前の指摘を残さない
- 指摘が残らなければ「指摘なし」とだけ書く
- 返すのは P0・P1・P2 の件数（反証を添えた P0 の件数を含む）と `<文書名>.review.md` のパスだけ
