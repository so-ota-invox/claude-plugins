# 起草の共通手順

起草の skill がすべて従う手順。工程によって変わる部分は各 skill の SKILL.md に書く。`<plugin>` は sdd plugin のディレクトリ（このファイルの 1 つ上）の絶対パス。agent は `<plugin>/procedures/agent.md` のとおりに起動する。

「止まる」と書いたところでは、理由をユーザーに示して終える。この手順に従う skill も続けない。

## 作業ブランチ

起草に入る前に、今のブランチがデフォルトブランチかを確かめる。デフォルトブランチが分からなければ、ユーザーに聞く。

- デフォルトブランチなら、最新のデフォルトブランチから作業ブランチを切ってよいかと、その名前を聞く。リポジトリにブランチ名の決まりがあれば、それに合わせた名前を勧める。よければ、デフォルトブランチを最新にしてから作業ブランチを作って切り替える。最新にできなければ止まる。断られたら、今のブランチのまま続ける
- デフォルトブランチでなければ、今のブランチのまま続ける。設計書と実装プランも、要件定義書と同じブランチで続けて書ける

## 再開

渡されたものが、`specs/` の下にもうある、この skill が書く種類の文書なら、再開する。状態が `approved` なら、そう伝えて止まる（承認済みの文書は、承認を取り消してから直す）。起草を飛ばし、その文書に要確認が残っていれば逆質問へ進む。残っていなければ、そう伝えて止まる。

## 起草

著者は、ユーザーが言わなければ `git config user.name` にする。それも空なら、ユーザーに聞く。書き出す先に文書がもうあれば、上書きしてよいかを先に聞き、よくなければ止まる。

1. 渡されたものが、よそで書かれた同じ種類の文書なら、調査と起草の代わりに `importer` で型へ写し、3 へ進む。`importer` には、著者と、`<plugin>/formats/common.md` の「元の文書」に従って決めた元の文書の値と、上流の行（設計書と実装プランだけ）を渡す
2. SKILL.md に挙げた調査の agent を起動し、報告を読んで、`<plugin>/formats/common.md` と自分の型に従って文書を書く。調査の報告はファイルに残さない
3. `<plugin>/skills/refine/SKILL.md` の手順で refine する

## 逆質問

1. 要確認を 1 問ずつ、推奨の答えを付けて、優先順位の高い順に聞く
2. 答えを受けたら、次の問いがあれば先に示し、その後で答えを文書に書き戻す。次の問いを示したときは、書き戻した後に何も書かずにターンを終える。反証の付いた P0 の要確認を人が退けたら、`<plugin>/formats/common.md` の「仮定」のとおりに書く
3. 要確認が尽きるか、ユーザーが止めたら終える
4. 逆質問で文書が変わっていたら、起草の 3 の refine をもう 1 度だけ行う
