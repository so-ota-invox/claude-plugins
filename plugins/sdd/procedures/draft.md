# 起草の共通手順

起草の skill がすべて従う手順。工程によって変わる部分は各 skill の SKILL.md に書く。`<plugin>` は sdd plugin のディレクトリ（このファイルの 1 つ上）の絶対パス。agent は `<plugin>/procedures/agent.md` のとおりに起動する。

「止まる」と書いたところでは、理由をユーザーに示して終える。この手順に従う skill も続けない。

## 作業ブランチ

起草に入る前に、今のブランチがデフォルトブランチかを確かめる。デフォルトブランチが分からなければ、ユーザーに聞く。

- デフォルトブランチなら、最新のデフォルトブランチから作業ブランチを切ってよいかと、その名前を聞く。リポジトリにブランチ名の決まりがあれば、それに合わせた名前を勧める。よければ、デフォルトブランチを最新にしてから作業ブランチを作って切り替える。最新にできなければ止まる。断られたら、今のブランチのまま続ける
- デフォルトブランチでなければ、今のブランチのまま続ける。基本設計書と詳細設計書も、要件定義書と同じブランチで続けて書ける

## 再開

渡されたものが、`specs/` の下にもうある、この skill が書く種類の文書なら、再開する。どの状態でも進め、状態は変えない。起草を飛ばし、その文書に要確認が残っていれば逆質問へ進む。残っていなければ、そう伝えて止まる。

## 起草

著者は、ユーザーが言わなければ `git config user.name` にする。それも空なら、ユーザーに聞く。書き出す先に文書がもうあれば、上書きしてよいかを先に聞き、よくなければ止まる。

1. SKILL.md に挙げた調査の agent を起動し、報告を読んで、`<plugin>/formats/common.md` と自分の型に従って文書を書く。調査の報告はファイルに残さない。渡されたもの（よそで書かれた文書を含む）は材料として次のように扱う
   - 意味を変えない。材料にある内容は、型の見出しに入らなくても落とさず、最も近い見出しに書く
   - 材料に無いことを、材料に書いてあったことにしない。調査で確かめたことか、仮定か要確認として書く
2. `<plugin>/skills/refine/SKILL.md` の手順で refine する

## 逆質問

1. 要確認を 1 問ずつ、推奨の答えを付けて、優先順位の高い順に聞く
2. 答えを受けたら、次の問いがあれば先に示し、その後で答えを文書に書き戻す。次の問いを示したときは、書き戻した後に何も書かずにターンを終える。反証の付いた P0 の要確認を人が退けたら、`<plugin>/formats/common.md` の「仮定」のとおりに書く
3. 要確認が尽きるか、ユーザーが止めたら終える
4. 逆質問で文書が変わっていたら、起草の 2 の refine をもう 1 度だけ行う

## 文書を変えたときの知らせ

もとからあった文書を変えたら（上書き、再開した文書への書き戻し、refine の反映）、終える前に次を報告する。

- 状態が `review` か `approved` なら、提出か承認の後で本文が変わったこと。`approved` なら、承認者の名前を添えて、承認者に確かめてもらうこととして挙げる。状態は変えない
- 同じ `specs/<slug>/` の下で、管理情報の「上流」にこの文書を挙げた文書。あれば、そのパスと著者を知らせる相手として挙げる。下流の文書は直さない
