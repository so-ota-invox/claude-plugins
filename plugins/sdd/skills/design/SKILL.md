# design

基本設計書を起草する。`<plugin>` は sdd plugin のディレクトリの絶対パス `${CLAUDE_PLUGIN_ROOT}`（置き換わっていなければ、この SKILL.md の 2 つ上）。

## 使うもの

- 型: `<plugin>/formats/common.md` と `<plugin>/formats/design.md`
- 手順: `<plugin>/procedures/draft.md`
- 調査の agent: `impact-analyst` と `convention-surveyor`。並べて起動する
- 前の工程は要件定義。上流の文書（`<plugin>/formats/common.md` の「上流」）と、呼び出しで渡されたほかのもの（チケット、画面の画像、よそで書かれた文書）を材料に書く

## 入口

- 渡されたものが `<plugin>/procedures/draft.md` の「再開」に当たれば、入口の残りを飛ばして、下の「起草」のとおり `<plugin>/procedures/draft.md` に従う。ただし、次の基本設計書は再開せず、親の基本設計書として扱う
  - 子の名前（パスでない名前）と一緒に渡されたもの
  - 要確認が残っておらず、「サブ機能分割」に子があるもの
- 親の基本設計書を渡されたら、下の「子」で子の名前を決める。置き場は `specs/<slug>/<子の名前>/design.md`
- 親を渡されなければ、`specs/<slug>/requirements.md` を上流の要件定義書とし、置き場は `specs/<slug>/design.md`。要件定義書が渡されなければ、パスを聞く
- ほかに渡されたものは材料として読む。チケットは使える手段（MCP など）で読み、読めなければ本文を貼ってもらう
- 上流の文書が無いか、状態が `approved` でなければ、そう伝えて止まる
- 上流の文書に要確認が残っていれば、パスと番号を示す。止まらずに続ける

## 子

- 親の基本設計書が `approved` でなければ、そう伝えて止まる
- 子の名前が 2 つ以上なら、子ごとに 1 回ずつ呼ぶよう伝えて止まる
- 子の名前が親の「サブ機能分割」に無ければ、そこに挙げた名前を示して止まる
- 子の名前が無ければ、「サブ機能分割」に挙げた子のうち design.md がまだ無いものを示し、どれを書くかを聞く。無ければ、そう伝えて止まる

## 起草

`<plugin>/procedures/draft.md` に従う。調査の agent には、上流の文書のパス、材料、子の名前（子のときだけ）、調べるリポジトリを渡す。

起草の 1 で、文書と一緒に画面モックを書く。

- 画面設計に挙げた画面ごとに、文書と同じディレクトリの `mocks/<画面>.html` に書き、画面設計からリンクする。画面が無ければ書かない
- 形は `<plugin>/formats/common.md` の「置き場」に従う
- 項目とふるまいは画面設計に揃える。エラー・空・権限で見え方が変わる状態も、画面設計に書いたものは描く
- 既存の画面を変えるときは、渡された画面の画像か、`convention-surveyor` が返した既存の画面の構成と部品に揃える

逆質問の答えで画面が変わったら、モックも直す。

## 報告

- 文書と HTML のパス、モックのパス
- refine の報告（逆質問の後に refine をもう 1 度行ったときは、その報告も）
- 残った要確認の件数
- 上流の文書に残っている要確認（パスと番号）
- 知らせる相手（`<plugin>/procedures/draft.md` の「下流の著者への知らせ」）
- 子に分けたときは、子を書くコマンド: `/sdd:design specs/<slug>/design.md <子の名前>`（Codex では `$sdd:design specs/<slug>/design.md <子の名前>`）。この文書が承認されてから使う
- レビューに出すときのコマンド: `/sdd:submit <文書>`（Codex では `$sdd:submit <文書>`）
